## 3. 测试目标

### 3.1 必须达到的目标

1. 每个回合只使用一个模型；工具循环中不得静默换模。
2. 技术故障可以切换模型，最多尝试 3 次，并留下可解释的 `attemptChain`。
3. 决策超时、决策方不可用或无决策 Key 时，请求仍能通过规则路由继续。
4. 流式响应逐块透传，不在代理层缓冲到流结束。
5. 模型健康状态能够正确冷却、恢复、三振停用和热重置。
6. API Key、Bearer Token、Authorization 头和任务原文不进入日志及诊断输出。
7. 桌面接入只修改 Jev 管理项，卸载后恢复用户原有配置。
8. 代理仅监听 `127.0.0.1`，不暴露到局域网或公网。
9. 现有 76 个测试不得回归，P0/P1 测试必须全部通过。

### 3.2 非目标

- 不把回答质量差自动判定为技术故障；质量问题通过 `/model` 手动换模处理。
- 不验证未实现的 Ollama、LM Studio、Laya 本地决策 Provider。
- 不承诺 Linux/macOS 桌面接入；非 Windows 平台只用于仓库级单元和集成测试。
- 不修改 Codex 登录状态、权限审批策略或 `auth.json`。
- 不在测试报告、日志或代码仓库中保存真实密钥、授权头和个人路径。

## 4. 测试策略

### 4.1 测试层级

| 层级 | 名称 | 执行方式 | 费用 | 发布要求 |
| --- | --- | --- | --- | --- |
| L0 | 静态门禁 | CI/本地命令 | 无 | 每次提交 |
| L1 | 单元测试 | `node --test` | 无 | 每次提交 |
| L2 | 代理与协议集成测试 | 本地 Mock 上游/决策 API | 无 | 每次提交 |
| L3 | CLI、MCP、桌面生命周期 | 隔离的 Windows 环境 | 无 | 每个发布候选版本 |
| L4 | 真实 Codex 和上游冒烟 | 已登录 Windows 环境 | 低 | 每个发布候选版本 |
| L5 | 性能、兼容性和稳定性 | Windows + Mock/真实上游 | 视配置 | 每个发布候选版本 |
| L6 | 四策略质量评测 | 真实模型，30 任务 x 4 策略 | 较高 | 正式发布前单独审批 |

### 4.2 优先级

| 优先级 | 定义 | 发布规则 |
| --- | --- | --- |
| P0 | 破坏路由正确性、回合一致性、数据安全、密钥隐私或配置还原 | 零失败、零未处理缺陷 |
| P1 | 核心命令、恢复能力、协议兼容和主要用户流程 | 全部通过；若豁免必须有审批和风险说明 |
| P2 | 性能、扩展性、质量收益和边缘兼容 | 达到指标；未达标需形成后续计划 |
| P3 | 观察性增强、低概率边缘场景 | 可进入待办，不默认阻断发布 |

### 4.3 自动化原则

- 确定性逻辑优先自动化，真实桌面菜单和真实账号链路保留人工验收。
- 每个测试必须隔离数据目录、配置文件和端口，测试之间不得共享可变状态。
- 网络测试默认使用 Mock；真实调用必须明确标记环境、预算和审批状态。
- 时间相关测试使用可注入时间或短周期参数，禁止依赖长时间真实等待。
- 测试失败必须保留原始响应、状态码和 `attemptChain`，但要先经过脱敏。

## 5. 测试环境

### 5.1 环境矩阵

| 环境 | 用途 | 配置要求 |
| --- | --- | --- |
| E0-CI | L0/L1/L2 回归 | Ubuntu，Node 20 和 24，`npm ci` |
| E1-Win | 本地无费用测试 | Windows 10 或 11，Node 20.12+，仓库干净副本 |
| E2-E2E | 桌面和 Codex 冒烟 | Windows，Codex CLI/桌面版已登录，独立 `CODEX_HOME` |
| E3-Real | 真实故障切换和质量评测 | 已审批的 Provider、模型档案和费用预算 |

真实端到端测试至少覆盖：

- Windows 11 + Node 20 + 文档指定 Codex 版本。
- Windows 10 或 Windows 11 + Node 24 + 当前支持的 Codex 版本。
- 如果只完成一个真实平台组合，必须在发布记录中明确剩余兼容性风险。

### 5.2 隔离要求

- 使用临时 `CODEX_HOME`，避免污染日常 Codex 配置。
- 使用独立 `JEV_DATA_DIR` 和 `JEV_PROFILES_DIR`。
- 使用空闲的 `JEV_PROXY_PORT`，测试前检查端口占用。
- 准备原始 `config.toml` 和 `auth.json` 的哈希，测试后逐项比较。
- 测试数据目录应位于临时目录或专门的测试工作区。
- 真实测试开始前创建可恢复备份；测试后验证备份存在且可读。

### 5.3 测试凭据

- 凭据只通过本机环境变量或被 Git 忽略的 `.env` 注入。
- 隐私测试使用唯一 canary 值，例如 `JEV-CANARY-20260928-LOCAL-ONLY`。
- 不得把 canary 以外的真实 Key 写入测试脚本、报告或命令历史截图。
- 所有输出扫描必须覆盖 stdout、stderr、`decisions.jsonl`、`latest.json`、桌面服务日志、健康接口、`status`、`explain` 和 MCP 响应。

## 6. 测试数据

### 6.1 模型池矩阵

| 场景 | 档位组合 | 关键条件 |
| --- | --- | --- |
| 单模型 | 1 个 medium | 无法切换时仍可完成或返回明确错误 |
| 小模型池 | low + medium | `auto` 策略不调用 Jev，使用规则 |
| 宽模型池 | low + medium + high | `auto` 策略调用 Jev |
| frontier 池 | 含 frontier | 默认排除，`JEV_ALLOW_LONG=1` 后才参与 |
| 工具能力 | 支持/不支持 tools | `requiresTools` 硬过滤或规则升级 |
| 运行状态 | 可用、冷却、永久停用 | 不得调用永久停用模型 |
| 上下文 | 足够、临界、不足 | 静态上限和 `contextRemaining` 同时验证 |
| 成本 | 有价格、无价格、超过 `maxCost` | 候选过滤结果可预测 |
| Provider | openai、deepseek、passthrough、缺失 | 执行 Provider 解析和缺配置错误 |

### 6.2 请求样本

- 短聊天、中文长任务、英文长任务、空白输入和非字符串输入。
- 含代码、堆栈、报错、测试、调试、重构、架构和翻译关键词的请求。
- 超过 50,000 token 估算值的输入和超过候选上下文上限的输入。
- 含 tools、function call、function output、custom tool output 的请求。
- `previous_response_id`、存在或缺少 `prompt_cache_key` 的请求。
- `stream: true` 和 `stream: false` 两种响应。
- 空 JSON、无效 JSON、缺 `model`、未知字段、超大 body 和畸形 Unicode。
- 决策方返回未知模型、低置信度、超时、500、空 body 和无效 JSON。

### 6.3 故障样本

| 故障类型 | 期望行为 |
| --- | --- |
| 401、403 | 可切换，计入模型健康 |
| 402、额度/余额错误 | 可切换，计入模型健康 |
| 404、`model_not_found` | 可切换，按账号/渠道错误冷却 |
| 429 | 可切换，指数冷却 |
| 529、5xx | 可切换，计入冷却 |
| 请求超时、连接失败 | 可切换，计入冷却 |
| 400/422 内容错误 | 可切换尝试，但不冷却模型 |
| 参数错误且不可重试 | 返回诊断，不无限重试 |
| 客户端断开 | 中止上游请求，不继续无意义切换 |
| 上游在响应头后断流 | 记录流中断，不重放已经输出的内容 |

### 7.14 质量评测

评测复用 `evals/tasks.json` 的 30 个任务，共执行 120 次：

| 策略 | 配置 | 目的 |
| --- | --- | --- |
| 全部最强模型 | 固定最强档 | 完成率和成本基线 |
| 全部最低成本模型 | 固定低档 | 低成本质量下界 |
| 静态规则 | `JEV_DECISION_PROVIDER=static` | 规则路由基线 |
| Jev 动态路由 | 默认动态配置 | 目标策略 |

执行要求：

- 在临时目录运行，不修改被测项目和用户仓库。
- 每次运行记录任务 ID、策略、模型/provider、完成状态、返工次数、耗时、token、估算成本和 `decisionId`。
- 同一任务各策略尽量在相同时间窗口和相似网络条件下执行。
- 评分标准在运行前固定，不能在看到结果后修改。
- 运行前确认费用预算；预算未批准时只生成计划，不发起真实调用。
- 质量评测属于 L6，不得混入无费用的 CI 回归。

验收指标：

- 完成率相对全强模型基线下降不超过 3 个百分点。
- 成本相对全强模型至少下降 20%。
- Jev 决策延迟 P95 <= 800ms。
- 同一回合非预期换模率 < 2%。
- 每个发布模型档案至少 20 个有效样本；不足时标记“未校准”。
